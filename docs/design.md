# 可視化3ページの統合設計

作成日: 2026-08-06
対象: `viz/index.html`, `viz/graph.html`, `viz/schools.html`
状態: ドラフト（未着手）

## 何を解くのか

3つの可視化はそれぞれ成立しているが、互いに切れている。ヒートマップで2019年の東京を見てフロー図へ移ると、年度は2015に戻り、注目していた県も消える。同じ「表で見る」が2ページに別実装で存在し、ツールチップは3ページとも別々に書かれていて出す情報が揃っていない。

利用者から見た問題は1つに集約できる。**「いま自分が何を見ているか」がページをまたいで保たれない。** 年度と注目県という2つの状態を、3ページが各自で持っては捨てている。

## 前提と制約

- 依存ライブラリなし。ビルド工程なし。`file://` で直接開けることを維持する。
- そのため `<script type="module">` は使えない（Chrome は file:// のモジュール読み込みを CORS で拒否する）。共通コードは従来型の `<script src>` とグローバル名前空間で渡す。`viz/data.js` が `const OD_DATA` を定義しているのと同じ方式に揃える。
- データは静的。全年度・全県ぶんを最初に読み込む（`viz/data.js` は94KB）。
- 配色は dataviz skill の palette を使用済みで、逐次ランプ（青100→700）、発散ペア（青↔赤）、カテゴリ3色（青・橙・緑）はいずれも validator を通してある。再設計でも同じ値を使い、色の選び直しはしない。

### データ契約

`viz/data.js` が定義する `OD_DATA` の形。`scripts/build_viz_data.py` が生成する。

| キー | 形 | 内容 |
| --- | --- | --- |
| `years` | `number[11]` | 2015〜2025 |
| `prefectures` | `string[47]` | 「北海道」「青森県」… JISコード順 |
| `shortNames` | `string[47]` | 接尾辞を落とした短縮名 |
| `regions` | `{name, size}[8]` | 地方ブロックと県数。合計47 |
| `matrix` | `number[11][47][47]` | `[年][出身高校所在地][大学所在地]`。対角は県内進学 |
| `local` / `outbound` / `inbound` / `netInflow` | `number[11][47]` | 県内進学 / 流出 / 流入 / 純流入 |
| `capacity` | `{total, national, public, private}` 各 `number[11][47]` | 大学所在地から見た入学者数。「その他」を含む |
| `schools` | `{year: 2025, high_schools, high_national, high_public, high_private, universities, university_national, university_public, university_private}` 各 `number[47]` | 学校数。2025年度のみ |

`schools` だけ単年度である。ここが時間軸の非対称の原因になっている。

## 設計

### 1. 共通シェル

3ページの上部に同一のヘッダを置く。中身は次の4つだけに絞る。

```
[ ヒートマップ | フロー図 | 設置数 ]   年度 ◀━━●━━▶ 2019  [▶再生]  [配色: 明]
```

- タブ: 現在地を `aria-current` で示す。リンク先には現在の状態をハッシュで引き継ぐ。
- 年スライダと再生: 3ページ共通。`schools` を表示中は2025で固定し、`disabled` にしたうえで「学校数は2025年度のみ」と注記を出す。動かせない理由を隠さない。
- 配色トグル: 現状どおり。

ビュー固有の操作（実数/構成比、地域、しきい値、大きさ、並び順、横軸）はシェルではなく各ビューのパネル内に残す。共通に上げるのは、全ビューで意味が同じものだけに限る。

### 2. URL ハッシュによる状態共有

ハッシュに載せる。ページ遷移でもリロードでも保たれ、URLを送れば同じ画面が再現できる。

```
#view=heatmap&year=2019&pref=13&mode=share&area=all&threshold=500
```

| キー | 値 | 既定 | 適用先 |
| --- | --- | --- | --- |
| `view` | `heatmap` / `graph` / `schools` | `heatmap` | 遷移先の判定 |
| `year` | 2015〜2025 の整数 | 2025 | 全ビュー |
| `pref` | JISコード 1〜47（`prefectures` の添字+1） | なし | 全ビュー |
| `mode` | `count` / `share` | `count` | heatmap |
| `area` | `all` / `east` / `west` | `all` | graph |
| `threshold` | 200〜5000 | 500 | graph |
| `size` | `send` / `take` | `send` | graph |
| `sort` | `count` / `density` / `code` | `count` | schools |
| `axis` | `ratio` / `density` | `ratio` | schools |

`pref` を添字ではなく JISコードにするのは、47都道府県の並びが JIS 順であり、`pref=13` が東京と読めるほうが URL として意味を持つため。読み込み時に `-1` して添字に戻す。

再生中の小数年度はハッシュに書かない。書くと履歴が汚れ、共有した URL が中途半端な補間位置を指す。ハッシュに入れるのは整数年度のみで、補間は実行時の状態に留める。

### 3. 選択県の詳細パネル

3ページに散らばっているツールチップと統計タイルを、1つの共有パネルに集約する。県が選ばれている間、どのビューでも同じ位置に出る。

パネルの内容（`pref` と `year` から一意に決まる）:

- 県名、その年度
- 送り出し（県内進学＋流出）、県内進学率
- 流出、流入、純流入
- 主な流出先・流入元 各3件
- 県内の大学の入学者数と国公私立の内訳
- 高校数・大学数と設置者別内訳（2025年度の値である旨を添える）
- 純流入の11年推移のスパークライン

これにより各ビューのツールチップは「そのマーク固有の情報」だけに縮む。ヒートマップなら2県間の人数と構成比、フロー図なら県の識別、散布図なら座標の2値。県の素性はパネルが引き受ける。

配置は画面幅で切り替える。960px以上なら右側に固定、それ未満なら図の下。

### 4. モジュール分割

```
viz/
  data.js              生成物。触らない
  shared/
    state.js           ハッシュの読み書き、変更通知（購読者に配る）
    theme.js           CSS変数の定義、明暗トグル、ランプ、色の混色
    format.js          数値・率の書式、県名、JISコードと添字の変換
    chrome.js          共通ヘッダの描画とタブ遷移
    panel.js           選択県の詳細パネル
    table.js           「表で見る」の共通実装
  index.html           ヒートマップ本体のみ
  graph.html           フロー図本体のみ
  schools.html         設置数本体のみ
```

各 HTML は `data.js` → `shared/*.js` → 自前スクリプトの順に読み込む。共有側はグローバルに `VIZ.state` `VIZ.theme` `VIZ.format` … として生やす。

CSS も同様に `shared/base.css` へ切り出す。3ページの `:root` 変数定義とパネル・ボタン・表の見た目は完全に同一で、現在は3回書かれている。

### 5. 各ビューの責務

統合後、3つのビューは「県または県ペアを選ぶ手段」として役割が分かれる。

- ヒートマップ: 全2,209組を一望し、2県間の関係を選ぶ。構造の把握。
- フロー図: 地理の上で1県の出入りを追う。方向と距離の把握。
- 設置数: 47県を2つの指標の平面に置き、外れ値を見つける。要因の検討。

同じ問いに3つの答えを出すのではなく、問いの段階が違うものとして並べる。タブの順序もこの順にする。

### 6. フロー図のズームと視認性

利用者からの指摘: ノードが小さすぎて見にくい、矢印が分かりにくい、拡大縮小したい。

原因は密集にある。現状は全47県を1枚に収めるため、ノード半径を `3 + 9 * sqrt(規模)` に抑えている。関東・近畿では県庁所在地が数十kmしか離れておらず、これ以上大きくすると団子になる。つまり「小さくしないと重なる」制約が視認性を縛っている。ズームはこの制約そのものを外す。

#### 変換の持ち方

canvas に `scale`（1.0〜8.0）と平行移動 `tx, ty` を持たせ、描画前に適用する。

- ホイール: カーソル直下の地点を固定したまま拡大縮小する。倍率は1ノッチ1.15倍程度
- ドラッグ: パン。カーソルは `grab` / `grabbing`
- ダブルクリックまたはリセットボタン: 等倍に戻す
- 地域プリセット（全国・東日本・西日本）は、その地域の外接範囲にフィットする変換値の設定として作り直す。現在の「投影を組み直す」実装は不要になり、投影は全国固定の1本になる
- ヒットテストは画面座標を逆変換してから行う

#### 拡大時に何を追随させるか

ここが設計の要になる。全要素を一律に拡大すると、密集はほどけず絵が大きくなるだけで終わる。

| 要素 | 拡大への追随 | 理由 |
| --- | --- | --- |
| 座標 | 完全に追随 | 地理関係を保つ |
| ノード半径 | 部分的に追随（`r * (1 + (scale - 1) * 0.35)`） | 完全追随だと密集が解けない。非追随だと点が散るだけ |
| 線幅・矢じり | ノード半径と同じ扱い | ノードとの比を保つ |
| ラベル文字 | 追随しない（画面上11px固定） | 拡大でノード間隔が開き、衝突回避を通るラベルが増える。これが最大の可読性向上になる |

拡大するほど、間引かれていた県名が自然に現れる設計にする。ラベルの衝突回避は現行の貪欲法をそのまま使う。

#### ノードの底上げ

ズームを前提にできるので、等倍時の大きさも上げる。最小半径3px→4.5px、最大12px→16px。しきい値の既定は500人のまま据え置き、密集は拡大で解く。

#### 矢印の追加改善

テーパーと矢じりは入れたが、等倍では依然として読みにくい。ズームで大半は解消する見込みだが、加えて次を検討する。

- 長いエッジには曲線の中間（70%位置）にも矢じりを置く。終点だけだと束の中で埋もれる
- 選択・ホバー中のエッジのみ、流れる破線で方向を示す。`prefers-reduced-motion` を尊重し、動きを止める設定では静止させる

#### ハッシュに載せるか

載せない。ズーム位置まで URL に入れると共有時に意図しない拡大状態を強制することになり、`area` プリセットとの整合も取りにくい。ズームは実行時の状態に留める。

## 段階

### Phase 1: フロー図のズームと視認性（他と独立、先行可能）

上記6節の実装。`viz/graph.html` の中だけで完結し、共通シェルの作業を待たない。利用者の指摘に直接応えるので最優先とする。

受け入れ条件:

- ホイールで拡大縮小、ドラッグでパン、ダブルクリックでリセットができる
- 等倍で読めなかった関東・近畿のノードが、拡大すると分離して県名が出る
- 地域プリセットがズーム状態の設定として動き、投影の組み直しが消えている
- 拡大してもラベルの文字サイズが変わらない
- 明暗どちらの配色でも確認済み

### Phase 2: 骨格

- `shared/state.js`, `shared/theme.js`, `shared/format.js`, `shared/base.css`, `shared/chrome.js` を作る
- 3ページから重複コードを削り、共通ヘッダに差し替える
- ハッシュ状態の共有を通す

受け入れ条件:

- ヒートマップで年度2019・東京を選び、フロー図タブへ移ると2019年・東京が選択された状態で開く
- 3ページのいずれの URL をコピーしても、別ウィンドウで同じ画面が再現される
- `file://` で開いて動作する
- 3ファイルの合計行数が現在の2,361行より減っている

### Phase 3: 詳細パネルと表の統合

- `shared/panel.js`, `shared/table.js` を作る
- 各ビューのツールチップをマーク固有の情報だけに縮める
- ヒートマップの統計タイルをパネルへ移す

受け入れ条件:

- 県を選んだとき、3ビューで同一の内容が同一の並びで出る
- 「表で見る」が1つの実装になり、各ビューの絞り込み条件を反映する

### Phase 4: 判断保留

1ページに統合して DOM ごと差し替える案は、Phase 3 まで終えてから要否を判断する。ページ遷移が体感で気にならなければ着手しない。

## やらないこと

- 配色の選び直し。validator を通した現行値を使う
- グラフDB（`graph/*.cypher`）側の変更。可視化とは独立している
- 学校数の時系列化。年度ごとに e-stat の分類IDを集める手間に対して、学校数は年に数校しか動かず、得るものが小さい
- ビルドツールの導入

## 検証

```bash
cd viz && python3 -m http.server 8931
```

Playwright で明暗それぞれのスクリーンショットを撮り、ラベルの衝突・はみ出し・凡例の欠けを目視する。加えて `file://` で直接開いて、サーバなしでも動くことを確認する。数値の検証は不要（`data.js` は変更しない）。

## 次のセッションへの引き継ぎ

このドキュメントを読めば実装に入れる状態にしてある。着手順は Phase 1 → 2 → 3。Phase 1 は `viz/graph.html` の中で完結するので、他を読まずに始められる。

現行コードで押さえておく箇所:

- `viz/graph.html` の `project()` が投影を組み立て、`points[]` に画面座標を持つ。ズーム導入でここを全国固定にし、変換は描画時に掛ける
- 同ファイルの `nodeAt()` がヒットテスト。逆変換を入れる場所
- `drawLabels()` の貪欲な衝突回避はそのまま使える
- `drawEdge()` がテーパー帯と矢じりを描く
