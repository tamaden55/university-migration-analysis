# 可視化3ページの統合設計

作成日: 2026-08-06
対象: `viz/index.html`, `viz/graph.html`, `viz/schools.html`
状態: Phase 1・Phase 2 実装済み。Phase 3 未着手。2026-08-08 に操作系を一新（「改訂: 操作系の一新」節）

## 何を解くのか

3つの可視化はそれぞれ成立しているが、互いに切れている。ヒートマップで2019年の東京を見てフロー図へ移ると、年度は2015に戻り、注目していた県も消える。同じ「表で見る」が2ページに別実装で存在し、ツールチップは3ページとも別々に書かれていて出す情報が揃っていない。

利用者から見た問題は1つに集約できる。**「いま自分が何を見ているか」がページをまたいで保たれない。** 年度と注目県という2つの状態を、3ページが各自で持っては捨てている。

## 前提と制約

- 依存ライブラリなし。ビルド工程なし。`file://` で直接開けることを維持する。
- そのため `<script type="module">` は使えない（Chrome は file:// のモジュール読み込みを CORS で拒否する）。共通コードは従来型の `<script src>` とグローバル名前空間で渡す。`viz/data.js` が `const OD_DATA` を定義しているのと同じ方式に揃える。
- データは静的。全年度・全県ぶんを最初に読み込む（`viz/data.js` は94KB）。
- 配色は dataviz skill の palette を使用済みで、逐次ランプ（青100→700）、発散ペア（青↔赤）、カテゴリ3色（青・橙・緑）はいずれも validator を通してある。再設計でも同じ値を使い、色の選び直しはしない。

### データ契約

`viz/data.js` が定義する `OD_DATA` の形。`scripts/build_viz_data.py` が生成する。

| キー | 形 | 内容 |
| --- | --- | --- |
| `years` | `number[11]` | 2015〜2025 |
| `prefectures` | `string[47]` | 「北海道」「青森県」… JISコード順 |
| `shortNames` | `string[47]` | 接尾辞を落とした短縮名 |
| `regions` | `{name, size}[8]` | 地方ブロックと県数。合計47 |
| `matrix` | `number[11][47][47]` | `[年][出身高校所在地][大学所在地]`。対角は県内進学 |
| `local` / `outbound` / `inbound` / `netInflow` | `number[11][47]` | 県内進学 / 流出 / 流入 / 純流入 |
| `capacity` | `{total, national, public, private}` 各 `number[11][47]` | 大学所在地から見た入学者数。「その他」を含む |
| `paths` | `{graduates, university, senmon, senshu_general, training, employed, other, unknown}` 各 `number[11][47]` | 出身高校所在地から見た卒業後の進路。`matrix` の行方向と同じ主語で、その分母にあたる |
| `schools` | `{year: 2025, high_schools, high_national, high_public, high_private, universities, university_national, university_public, university_private}` 各 `number[47]` | 学校数。2025年度のみ |

`schools` だけ単年度である。ここが時間軸の非対称の原因になっている。

`paths` は `matrix` の行合計と主語が同じだが、数は一致しない。OD 表は過年度卒（浪人）を含む入学者数で、`paths` は当年3月卒業者の進路だからである。`paths.university` には通信教育部や高等学校専攻科への進学も含む。差分を見るぶんには問題ないが、水準を引き算してはいけない。

## 設計

### 1. 共通シェル

3ページの上部に同一のヘッダを置く。中身は次の3つだけに絞る。

```
同じデータの見方                        年度
[ ヒートマップ | フロー図 | 設置数 ]    ◀━━●━━▶ 2019年度        [配色: 明]
    県×県の行列  地図上の流れ  受け皿と進路
```

- タブ: 現在地を `aria-current` で示す。リンク先には現在の状態をハッシュで引き継ぐ。各タブに切り口の副題を添える。名前だけでは別々の3ページに見え、同じデータを3通りに見ているという関係が読めない。
- 年スライダ: 3ページ共通。11年度の離散ステップで、右横に年度を出す。`schools` を表示中は2025で固定し、`disabled` にしたうえで「学校数は2025年度のみ」と注記を出す。動かせない理由を隠さない。
- 配色トグル: 現状どおり。

タブ群とスライダにはそれぞれ見出しを付ける。見出しのない裸のボタン帯を2段に並べると、何を変える道具なのかが読めない。

ビュー固有の操作（実数/構成比、並び順、横軸）はシェルではなく各ビューのパネル内に残す。共通に上げるのは、全ビューで意味が同じものだけに限る。

### 2. URL ハッシュによる状態共有

ハッシュに載せる。ページ遷移でもリロードでも保たれ、URLを送れば同じ画面が再現できる。

```
#view=heatmap&year=2019&pref=13&mode=share
```

| キー | 値 | 既定 | 適用先 |
| --- | --- | --- | --- |
| `view` | `heatmap` / `graph` / `schools` | `heatmap` | 遷移先の判定 |
| `year` | 2015〜2025 の整数 | 2025 | 全ビュー |
| `pref` | JISコード 1〜47（`prefectures` の添字+1） | なし | 全ビュー |
| `mode` | `count` / `share` | `count` | heatmap |
| `sort` | `count` / `density` / `code` | `count` | schools |
| `axis` | `ratio` / `density` | `ratio` | schools |

`pref` を添字ではなく JISコードにするのは、47都道府県の並びが JIS 順であり、`pref=13` が東京と読めるほうが URL として意味を持つため。読み込み時に `-1` して添字に戻す。

ハッシュに入る年度は整数のみ。スライダが11段の離散なので、手を動かすたびにそのまま書ける。

`pref` は3ビューで持つものの形が違うので、次のように読み替える。

| ビュー | `pref` を書くとき | `pref` を読むとき |
| --- | --- | --- |
| heatmap | 固定したセルの行（出身県）。どの県から出た流れを見ているかが主語になる | その県の対角セル（県内進学）を固定する。行と列の両方が引き立ち、注目が図に出る |
| graph | 選択した県 | その県を選択する |
| schools | クリックした円の県 | その円と、2つの表の該当行を強調する |

配色はハッシュに載せず `localStorage` に置く。ハッシュに入れると、共有した URL が受け取り手に送り手の明暗を強制することになる。`file://` で `localStorage` が使えない環境では OS 設定に従うだけで、動作は壊さない。

ズーム位置も載せない（6節）。フロー図は開くたび全国から始め、手で拡大・移動した状態は実行時に留める。

### 3. 選択県の詳細パネル

3ページに散らばっているツールチップと統計タイルを、1つの共有パネルに集約する。県が選ばれている間、どのビューでも同じ位置に出る。

パネルの内容（`pref` と `year` から一意に決まる）:

- 県名、その年度
- 送り出し（県内進学＋流出）、県内進学率
- 流出、流入、純流入
- 主な流出先・流入元 各3件
- 県内の大学の入学者数と国公私立の内訳
- 高校数・大学数と設置者別内訳（2025年度の値である旨を添える）
- 純流入の11年推移のスパークライン

これにより各ビューのツールチップは「そのマーク固有の情報」だけに縮む。ヒートマップなら2県間の人数と構成比、フロー図なら県の識別、散布図なら座標の2値。県の素性はパネルが引き受ける。

配置は画面幅で切り替える。960px以上なら右側に固定、それ未満なら図の下。

### 4. モジュール分割

```
viz/
  data.js              生成物。触らない
  shared/
    state.js           ハッシュの読み書き、変更通知（購読者に配る）
    theme.js           CSS変数の定義、明暗トグル、ランプ、色の混色
    format.js          数値・率の書式、県名、JISコードと添字の変換
    chrome.js          共通ヘッダの描画とタブ遷移
    panel.js           選択県の詳細パネル
    table.js           「表で見る」の共通実装
  index.html           ヒートマップ本体のみ
  graph.html           フロー図本体のみ
  schools.html         設置数本体のみ
```

各 HTML は `data.js` → `shared/*.js` → 自前スクリプトの順に読み込む。共有側はグローバルに `VIZ.state` `VIZ.theme` `VIZ.format` … として生やす。

CSS も同様に `shared/base.css` へ切り出す。3ページの `:root` 変数定義とパネル・ボタン・表の見た目は完全に同一で、現在は3回書かれている。

### 5. 各ビューの責務

統合後、3つのビューは「県または県ペアを選ぶ手段」として役割が分かれる。

- ヒートマップ: 全2,209組を一望し、2県間の関係を選ぶ。構造の把握。
- フロー図: 地理の上で1県の出入りを追う。方向と距離の把握。
- 設置数: 47県を2つの指標の平面に置き、外れ値を見つける。要因の検討。

同じ問いに3つの答えを出すのではなく、問いの段階が違うものとして並べる。タブの順序もこの順にする。

### 6. フロー図のズームと視認性

利用者からの指摘: ノードが小さすぎて見にくい、矢印が分かりにくい、拡大縮小したい。

原因は密集にある。現状は全47県を1枚に収めるため、ノード半径を `3 + 9 * sqrt(規模)` に抑えている。関東・近畿では県庁所在地が数十kmしか離れておらず、これ以上大きくすると団子になる。つまり「小さくしないと重なる」制約が視認性を縛っている。ズームはこの制約そのものを外す。

#### 変換の持ち方

canvas に `scale`（1.0〜8.0）と平行移動 `tx, ty` を持たせ、描画前に適用する。

- ホイール: カーソル直下の地点を固定したまま拡大縮小する。倍率は1ノッチ1.15倍程度
- ドラッグ: パン。カーソルは `grab` / `grabbing`
- ダブルクリックまたはリセットボタン: 等倍に戻す
- 地域プリセット（全国・東日本・西日本）は、その地域の外接範囲にフィットする変換値の設定として作り直す。現在の「投影を組み直す」実装は不要になり、投影は全国固定の1本になる
- ヒットテストは画面座標を逆変換してから行う

#### 拡大時に何を追随させるか

ここが設計の要になる。全要素を一律に拡大すると、密集はほどけず絵が大きくなるだけで終わる。

| 要素 | 拡大への追随 | 理由 |
| --- | --- | --- |
| 座標 | 完全に追随 | 地理関係を保つ |
| ノード半径 | 部分的に追随（`r * (1 + (scale - 1) * 0.35)`） | 完全追随だと密集が解けない。非追随だと点が散るだけ |
| 線幅・矢じり | ノード半径と同じ扱い | ノードとの比を保つ |
| ラベル文字 | 追随しない（画面上11px固定） | 拡大でノード間隔が開き、衝突回避を通るラベルが増える。これが最大の可読性向上になる |

拡大するほど、間引かれていた県名が自然に現れる設計にする。ラベルの衝突回避は現行の貪欲法をそのまま使う。

#### ノードの底上げ

ズームを前提にできるので、等倍時の大きさも上げる。最小半径3px→4.5px、最大12px→16px。しきい値は500人のまま据え置き、密集は拡大で解く。

#### 向きの示し方

当初は「起点側が太く、行き先へ細くなる帯」で向きを示していたが、これは効いていなかった。幅の変化は曲線の全長にわたって少しずつ効くので、目では追えない。しかも太さは人数の担当でもあり、2つの意味を1つの channel に載せていた。

やめて、線は一定幅（太さは人数のまま）、向きは矢じりだけに担わせる。そのぶん矢じりを大きくする。大きさは線の太さにほとんど依存させず、下限を置く（等倍で10px）。細い線でも向きが読めなければ意味がない。

長い流れには終点だけでなく途中にも等間隔で置く（190pxごと、最大3つ）。終点の矢じりは束の中で埋もれるし、画面の端で切れている流れは終点そのものが見えない。

#### 量の偏りを見せる

東京を選んでも一極集中が伝わらなかった。原因は濃さを一律にしていたこと。県を選ぶと最小人数が30人まで下がるので、東京には流入46本・流出46本の線が出る。本数は釣り合うが量は3倍以上違う。それを太さだけに任せていた。

太さの尺度は平方根で差を圧縮するうえ、どんなに小さい流れにも最低幅がある。結果、細い線が本数で押し勝ち、両方向が同じ重みに見えていた。

濃さにも人数を載せる。べき乗（0.4）は純流入の配色と同じ考えで、中位の流れにも濃さを届かせるため。定義域は太さと同じく全年度で固定し、年をまたいで濃さを比べられるようにする。

これで東京を選ぶと、濃く太い青が四方から集まり、赤は隣接3県を除いて背景へ沈む。量の偏りが形として出る。

#### 地図の線では量を比べられない

濃さを入れてもまだ東京一極集中は伝わらなかった。ここには地図としての構造的な限界がある。

目に入るインクの量は「太さ × 長さ」で決まる。長さは地理に固定されているので、量を担えるのは太さだけになる。神奈川から東京への21,550人は線の長さが15pxしかなく、北海道からの2,700人は450pxある。8分の1の流れが20倍のインクを持つ。しかも最上位3件（神奈川・埼玉・千葉）はいずれも隣接県なので、線がノードの内側に埋もれて太さを見せる場所すらない。

2つで応じる。

1. 近い相手ほど制御点を大きく膨らませ、線が姿を現す場所を作る。画面上で52pxは横へ張り出させる。膨らませると弦と曲線が離れるので、矢じりの位置は弦ではなく曲線に沿って求め直す（終点の円に触れる t を後ろから探し、その点の速さで手前へ戻す）
2. 選択県の札に、流入・流出の量を棒で出す。目盛りは全年度・全県を通じた1県の最大（東京の流入）を満杯とする共通の物差しで、県を変えても伸び縮みしない。東京を選べば満杯近く、大阪を選べば3割弱、高知を選べばわずか、と同じ棒の上で比べられる

線と棒で役割を分ける。線は「どこへ向かうか」、棒は「どれだけか」。地図が構造的に答えられない問いを、地図の中に置いた棒が引き受ける。

#### 操作が何を変えるのかを見せる（2026-08-08 に撤回）

「大きさ [送り出し|受け入れ]」のボタンが何を制御しているのか読めなかった。ラベルを「ノードの大きさ」に改め、選んでいるほうの意味を地の文で添え、切り替えを 0.42秒のトゥイーンで飛ばさずに移した。

これでも足りなかった。説明とアニメーションを足しても、東京以外では2つの定義の差が小さく、押した結果として何が変わったのかが伝わらない。操作そのものを畳んだ（「改訂: 操作系の一新」節）。説明で埋めようとした時点で、操作の側に無理があったと見るべきだった。

#### 色の意味を図の中へ

県を選ぶと流出が赤、流入が青になるが、この対応を図の外の凡例に置くと、線を見るたび視線を往復させることになる。選択した県のすぐ横に小さな札を出し、そこに「◯◯から」（赤・県から離れる向きの矢印）「◯◯へ」（青・県へ向かう矢印）と書く。札は県に付いて動くので、拡大しても移動しても目の位置から離れない。

下の凡例からは流出・流入の項目を落とす。同じことを2箇所で言わない。

#### 表示領域の取り方

図の枠は固定の 680×700 ではなく、画面から取る。高さは画面の 78%（下限700px・上限1000px）、幅は枠いっぱい。

当初はこのページだけ紙幅を 1560px まで広げていた。図が主役だからという理由だったが、3ページのうち1枚だけが違う幅になり、タブを移るたびに枠が飛んだ。2026-08-08 に 980px へ揃えた（「改訂: 操作系の一新」節）。等倍で全国を出すときの大きさを決めるのは高さのほうなので（日本は縦に長く、外接範囲の幅÷高さ ≒ 0.85）、幅が縮んでも等倍の図は小さくならない。拡大して1県の出入りを追うときに幅が効くが、そこはパンで足りる。

幅の取り方には別の失敗もある。幅を高さの1.15倍で抑えて中央に置いたところ、canvas の背景色とパネルの背景色が同じために境目が見えず、「余白があるのに絵が切れている」状態になった。切れ目は枠の縁と一致させること。

等倍では左右に余白が残るが、これは地理の形からくるもので、歪めない限り消せない。代わりに図の面へ細い縁を引いて、どこまでが図なのかを見えるようにする。

#### 拡大すると全体が見えない

ズームは手元を読めるようにする代わりに、全体のどこを見ているのかを奪う。縮尺の小さい全体図を右下に重ね、いま見えている範囲を枠で示す。枠の外は伏せる。等倍付近（1.05倍以下）では出さない。見失いようがないため。

全体図の中は数値を読む場所ではなく現在地を知る場所なので、県は点に留め、選択中の県だけ色を変える。クリックとドラッグで、指した地点を本図の中心へ持ってこられる。

#### 下敷きの地図

ノードの位置関係だけでは、どこを見ているのかが読めないという指摘があった。県の輪郭を薄く敷く。

データは都道府県の境界 GeoJSON（[dataofjapan/land](https://github.com/dataofjapan/land)）を `scripts/build_japan_map.py` で間引いたもので、`viz/japan.js` が `const JAPAN_MAP` を定義する。`data.js` と同じ方式なので `file://` の制約は変わらない。元は13MBあるが、Douglas-Peucker（許容 0.008度 ≒ 800m）と座標の丸め（3桁 ≒ 100m）で125KBまで落とす。下敷きに要るのは輪郭であって面積ではないので、この精度で足りる。

2つ決めごとがある。

遠い島は描かない。投影の範囲は描くものの外接矩形で決まるので、北方領土・小笠原・大東・先島・奄美まで含めると図全体が縮んで本土が潰れる。輪郭が丸ごと窓（緯度29.8〜46.0、経度128.0〜146.0）に入るものだけ残す。

沖縄は入れ図にする。フロー図は以前から沖縄のノードを那覇ではなく九州の南西（30.70, 128.20）へ寄せている。地図だけ実位置に描くとノードが海に浮くので、地図も同じだけずらし、破線の枠で囲って「ここだけ位置が違う」ことを見せる。ずらす量は `COORDS` が決めているので、データ側ではなく `graph.html` が持つ。

投影の範囲はノードだけでなく地図まで含めて取る。ノードだけで決めると北海道の北半分が枠の外に出るためで、そのぶん等倍の図は縦方向で約8割に縮む。切れた海岸線より読みにくいものはないと判断した。密集はズームで解く方針は変えていない。

濃さは、地の色から文字色へ 6%（暗色は10%）寄せた面と、24%（同30%）寄せた線。細い島は面が出ないので、読めるかどうかは線の側で決まる。線幅には下限を置く。

#### ハッシュに載せるか

載せない。ズーム位置まで URL に入れると共有時に意図しない拡大状態を強制することになる。ズームは実行時の状態に留める。

## 段階

### Phase 1: フロー図のズームと視認性（完了）

上記6節の実装。`viz/graph.html` の中だけで完結し、共通シェルの作業を待たない。利用者の指摘に直接応えるので最優先とする。

実装時に設計から動かした点:

- 地域プリセットから絞り込みを外し、純粋な視点設定にした。ズームがある状態で絞り込みを残すと、「東日本」で拡大したまま西へパンしたときに何も描かれない画面が作れてしまう。範囲外へ向かう流れも切れずに残るので、越境の流れが追える
- パンの可動域を2段にした。投影の枠に収める条件だけでは、日本が枠を斜めに走る帯であるために北西・南東の隅で1県も映らない眺めが作れた。画面中心から最寄りの県までを画面の半分の 0.55 以内に保つ条件を足してある
- 流れる破線での方向表示は見送った。ズームで大半が解消し、常時 rAF と `prefers-reduced-motion` の面倒に見合わない。曲線70%位置の矢じりだけ入れた

## 改訂: 操作系の一新（2026-08-08、issue #9）

Phase 1・2 を通した結果、操作が2段になった。上段の共通ヘッダに「タブ・再生・スライダ・配色」、下段の各パネルに「エリア・ノードの大きさ・しきい値・実数/構成比・選択を解除」。どちらも見出しのないボタン帯なので、正体不明の帯が2段重なった状態に見えていた。

見出しを足すだけでは解けない。下段の操作の多くは、押しても図の変化が読み取れず、置いておく理由のほうが薄かった。畳めるものを畳んでから、残ったものに見出しを付ける。

畳んだもの:

| 消したもの | 理由 |
| --- | --- |
| 自動再生と再生ボタン | 見ている年度が勝手に変わる。スライダで手を動かすほうが、どの年を見ているかを手放さずに済む。あわせて年度の補間もやめ、スライダを11段の離散にした |
| 「選択を解除」（3ページ） | 同じマークの再クリックで解除できる。マウスの側に移った操作をボタンにも残すと、2通りのやり方を覚えることになる |
| エリア選択（全国/東日本/西日本） | ズーム・パン・全体図が入った時点で、視点を移す手段として重複していた |
| ノードの大きさ切替（送り出し/受け入れ） | 東京以外では2つの定義の差が小さく、押した結果が読めない。送り出し＋受け入れの合計で固定した |
| しきい値スライダ | 動かしても線の増減が図の印象を変えず、何のための操作か伝わらない。500人で固定し、値は読み方の文と脚注に書いた |

残した操作には見出しを付けた。共通ヘッダは「同じデータの見方」（タブ）と「年度」（スライダ）の2組だけになり、各タブには切り口の副題（県×県の行列 / 地図上の流れ / 受け皿と進路）を添えた。3枚が別々のページではなく同じデータの3つの断面であることを、タブ自身に言わせる。

図の読み方の文は、ページ冒頭から図と同じ枠の中へ移した。冒頭に置くと、読むときには図が見えず、図を見るときには文が視野の外にある。

ただしフロー図では、移したうえで消した。凡例が色と太さの意味を持ち、選択県の札が向きを示し、ヒント行が操作を言う。同じことを文でもう一度書くと、図が自分で説明している状態を文のほうが壊す。しきい値のような図から読み取れない前提だけを脚注に残す。

ヒートマップの「実数 / 流出構成比」は語が抽象的で違いが伝わらなかった。「入学者数 / 行き先の割合」に改め、選んだほうの分母を1行で言い切るようにした。

紙幅は `--content-width`（980px）に集約し、3ページとも同じ幅にした。フロー図だけ 1560px だったため、タブを移るたびに枠が飛んでいた。

## 配信とキャッシュ

GitHub Pages は `cache-control: max-age=600` を返す。ブラウザは10分のあいだ再検証せずに手元のものを使うので、配信直後の再訪者には古い js と css が渡る。HTML だけ新しく js が古いと、増えたキーのないデータで動くことになり、画面が壊れる。実際に `paths` を足した配信で起きた。

`scripts/stamp_assets.py` が、`viz/*.html` の読む自前の js/css に `?v=<中身のハッシュ>` を打つ。URL が変われば別の資源として取りに行き、中身が変わらなければ版も変わらないのでキャッシュはそのまま効く。`build_viz_data.py` の最後から呼ばれる。css や `shared/*.js` だけを直したときは単体で実行する。

版を打ち忘れても画面が死なないよう、設置数ページには `paths` がないときの逃げ道を残してある。ヘッダは消さない。消すとタブまで無くなり、壊れた画面から出られなくなる。

## やらないこと

- 配色の選び直し。validator を通した現行値を使う
- グラフDB（`graph/*.cypher`）側の変更。可視化とは独立している
- 学校数の時系列化。年度ごとに e-stat の分類IDを集める手間に対して、学校数は年に数校しか動かず、得るものが小さい
- ビルドツールの導入

## 次のセッションへの引き継ぎ

残るは Phase 3（詳細パネルと表の統合）。共有側の足場はできているので、`shared/panel.js` と `shared/table.js` を足し、各ビューのツールチップをマーク固有の情報だけに縮める作業になる。

共有側で押さえておく箇所:

- `shared/state.js` の `SPEC` がハッシュのキーの全定義。キーを増やすならここだけ触る。`patch()` は購読者を呼ばない（自分の変更が自分へ戻るため）。外からの変更は `onChange`、書き込み自体の通知は `onWrite`
- `shared/chrome.js` が年度を持つ。ビューは `VIZ.chrome.yearIndex()` で年度を引く。`frame()` は `{low, high, f}` を返す枠が残っているが、いまは常に `f = 0`（自動再生を廃したので中間の年度が存在しない）。`mount({onYear, onTheme})` で再描画を受け取る
- `shared/theme.js` の `read()` が canvas・SVG 用に CSS 変数を実値で返す。3ページぶんの色をまとめて返すので、使わない項目があってよい
- 各ページの `set〜(value, { silent })` は、URL から復元する時に `silent: true` で呼ぶ。読んだ値をそのまま書き戻さないため
